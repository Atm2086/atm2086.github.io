# 格理论和单调框架

1. 常用于数据流分析和优化
2. 格理论：工具
3. 单调框架：求解数据流分析问题的一般框架

以具体的案例为主线：零值分析，分析程序P中的变量以及表达式是否有可能取值为0

# 格

## 格由来

1. 不可能静态穷举所有可能值
    - 希望定义一个**抽象有限论域**来刻画对变量x可能值
    - 可以暂且理解为分类的方式
    - 如零值分析抽象成四类，这四类组成一个论域：
        1. 未赋值或者非法值
        2. 零值
        3. 任意非零值
        4. 任意值
2. 定义完抽象后，关注点转向，不同状态之间的变化过程，在一个程序中不同状态间关系（有点像状态机或者集合？），抽象为**转移函数**
    - 具体比如：
        - 偏序关系
        - 公共先祖
        - 数据流方程
    - 估计是因为是状态机模型，所以会说转移函数
        - 转移函数和数据流和具体程序有关
            - 即转移函数的细致刻画：针对不同情况定义运算
        - 比如：
            1. 赋值为具体常量
            2. 赋值为变量
            3. branch情况
            4. 函数情况
3. **迭代**到 IN 和 OUT 都不变，即到达不动点，即是 IN 和 OUT 在这个抽象域里静态的所有可能值
    1. 能不能这么干取决于是否满足单调性和有界性
        - 转移函数的单调性：在运算前后能不能保证某种单调关系
        - 有界性


零值分析抽象论域：
$$
L = \left\{ \bot, 0, Z^{-0}, \top \right\},
$$

前向数据流方程：
$$
In[n] = \bigsqcup_{p \in pred[n]} Out[p]
$$

转移函数：变量到有限域的映射，结合数据流方程和具体的程序点信息，形成转移函数
$$
Out[n] = \mathcal{V}(n, In[n])
$$

## 格概念

偏序关系（一个关系如果能够满足）：S x S
1. 二元关系
2. 需要符合：
    - 自反性：要求所有S内元素满足
    - 传递性：
        - 如果存在偏序关系，则偏序关系得传递成立
    - 反对称
        - 如果两个元素之间存在两个反向的偏序关系，则一定是同一个元素
3. **偏序集和全序集**
    - 如果任意两个元素之间都存在关系，称为全序集
    - 如果仅仅存在这种关系，并不是任意两个元素都能满足，称为偏序集

上下界：
1. 用所有元素对某个形成同一个偏序关系来定义
2. 上下界未必唯一，但最小上界和最大下界唯一
3. 一个偏序集未必有上下界

**最小上界和最大下界**：
1. 允许唯一上界作为最小上界，唯一下界作为最大下界
2. 如果上界集合或者下界集合里有多个元素且形成偏序关系，必须保证最下层的上界或者最上层的下界唯一，不允许顺延。

上界：
$$
a \sqcup b
$$

下界：
$$
a \sqcap b
$$

**哈斯图**（Hasse）：**将偏序关系结合节点，可以形成有向图**。通常可以用这个刻画关系。并通过区分上下来作为上下界。

最小上界和最大下界在哈斯图中体现为：**如果两个元素存在最小上界，它在图形的路径上，一定是指向它们的“最直接的下一站”，而绝对不能是更远、更高的“上上一层”或“高层总领袖”**。

对于**格**来说：如果一个给定偏序集的元素任意两个元素同时能够拥有最小上界和最大下界

## 特殊类型格

上文对格的定义是最弱化的，只限制了任意两个元素的关系，对于多个元素之间的关系没有碰。

1. 完全格：每一个子集都存在最小上界和最大下界。从哈斯图的角度来说，上下唯一封死且上下贯通。
    - 如果一个完全格，函数是单调函数，则有塔斯基不动点
    - 因为上下唯一且封死，所以有顶元和底元
    - 因为上下贯通，所以能定义格的高度：
        - 从底元到顶元的最长路径长度（感觉可以理解为，在这里想要决出高下最多需要的步数）

2. 幂集格：一个有限集的所有子集（即幂集）构成的完全格
    - 高度等于原有限集的元素个数

3. 平坦格：高度为2的完全格（哈斯图，3层）

4. 乘积格：相当于 N 个完全格的积。
    - 乘积格的高度是所有格高度的和：理解为，想决出高下最多需要把每个地方最多需要把每一项的最多比较次数走一遍

5. 映射格：将 集合A 映射到一个 完全格L 上，注意比较的是映射，也就是说映射可以是不一样的，但是如果映射间具有偏序关系，需要保证不同映射转换到完全格上的时候保持同样的偏序关系。
    - 所以映射格的高度是，集合A 的元素数量 乘上 完全格的高度，因为要把所有可能按照最坏情况算一下。

## 单调性和不动点

单调性：即函数不改变其输入的偏序关系，虽然输入可能是一个格，输出可能是另外一个不同的格，不同格上的偏序关系可能定义不同，但是函数不改变其中的偏序状态。


不动点：在输入输出属于同一个集合上的函数如果有，输入输出一致，这个一致的点就是不动点。
- 如果有多个不动点，那么这些不动点形成的也是一个完全格
- 最小不动点：不动点如果有多个，且满足偏序关系，那么下界是最小不动点。

**Kleene不动点**：单调约束函数、有限高度完全格，就能迭代到唯一的最小不动点上。
- 注意这个不动点，本质是你所取状态转移函数/约束函数在当前偏序关系上的最终最保守描述。


所以如果是数据流上，就会产生一些计算不动点的算法：
- 朴素不动点算法：
    - 直接迭代，迭代到最后不变了就好了
- 其他算法


# 单调框架

对程序的数据流分析进行建模：`(G,L,f)`
1. 输入：控制流图 G 和 高度有限的完全格 L
2. 约束函数/状态转移函数 f
3. 数据流的建模：
    - IN：每条语句执行前状态建模
    - OUT：每条语句执行后状态建模

注意：**节点每次起步是格的最低状态，这个状态加上单调函数能够保证，其无法回头，所以一直往上走**。

---
证明如下：
现在，我们让迭代开始：

- **第 0 步：** 初始状态是 $x_0 = \bot$。

- **第 1 步：** 计算一次约束函数，得到 $x_1 = f(\bot)$。

- **比大小：** 因为 $\bot$ 是底座，任何其他元素都必须大于或等于它。所以，必然有：

  $$
  \bot \leq f(\bot) \implies x_0 \leq x_1
  $$

- **几何表现：** 第一步计算完，节点要么留在原地（如果 $f(\bot) = \bot$，此时就撞上了不动点），要么**必定向上移动**。

现在，第一步已经实现了 $x_0 \leq x_1$（向上移动了）。  
接下来算第二步：$x_2 = f(x_1)$。

这时候，函数的**单调性（Monotonicity）**跳出来开始接管一切。单调性的数学要求是：

$$
\text{如果 } A \leq B \quad \text{那么必然 } f(A) \leq f(B)
$$

我们把上一轮的结果（$x_0 \leq x_1$）当作 $A$ 和 $B$ 代入这个单调性公式：

$$
\text{因为 } x_0 \leq x_1 \quad \text{所以必然 } f(x_0) \leq f(x_1)
$$

而根据定义，$f(x_0)$ 就是 $x_1$，$f(x_1)$ 就是 $x_2$。我们把它翻译回来，就得到了：

$$
x_1 \leq x_2
$$

- **几何表现：** 第二步计算完，节点依然只能**继续向上移动**（或者留在原地）。

以此类推，通过数学归纳法，每一轮的计算都会被上一轮的单调性死死扣住：

$$
x_0 \leq x_1 \leq x_2 \leq x_3 \leq \cdots \leq x_k \leq x_{k+1}
$$

**你看，链条被单调性锁死了，它在几何哈斯图上只能像爬楼梯一样一阶一阶往上拔高，完全找不到任何一个能让它掉头“往下移动”的数学漏洞。**

## 高效求不动点的算法

以 CFG 控制流图为框架。

两个根据不同控制流方向划分的基本数据流分析技术：
1. 到达定值分析（是一个前向分析操作，得从前置依赖往后）
    - 帮程序里的某一次变量使用，寻找所有可能给它赋过值的“源头”。这一行x的值是第几行赋值的。
    - 比如常量传播会用这个来确定唯一的源。
2. 活跃分析（是一个后向分析操作，需要从后继节点出发计算得到前驱节点的数据流值）
    - 这个变量未来会不会被用到
    - 如死代码消除、寄存器分配

为什么朴素不动点计算存在冗余：
1. 许多已经收敛但重算的点，且这些重算可能是必要的
2. 一人得病全家住院

### Worklist 算法

1. 朴素不动点算法，是将所有一串代码当作一个约束，集体迭代
2. WorkList 算法：
    1. 按照拓扑序遍历 CFG 节点
    2. 工作集：如果当前节点没迭到不动点上，就要把他影响的下游加进工作集，直到工作集为空
